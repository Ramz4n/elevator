# Система учёта заявок лифтовой службы

Набор из трёх приложений для диспетчерской лифтовой службы. Все они работают с одной общей базой MariaDB: заявки ведут диспетчеры в десктопном приложении, а сайт и Telegram-бот эти данные только читают.

| Проект | Для кого | Что делает | Стек |
| --- | --- | --- | --- |
| [elevator_desktop](https://github.com/Ramz4n/elevator_desktop) | диспетчеры | журнал заявок: создание, редактирование, поиск, справочники адресов и сотрудников, резервные копии | Python, Tkinter, Windows `.exe` |
| [elevator_web](https://github.com/Ramz4n/elevator_web) | руководство, инженеры | просмотр заявок и статистики через браузер, паспорт объекта | Python, Flask, waitress, memcached |
| [elevator_telegram_bot](https://github.com/Ramz4n/elevator_telegram_bot) | механики | выбор лифта по адресу и просмотр истории заявок по нему | Python, aiogram 3, asyncmy |

## Как это устроено

```
 Диспетчерские ПК                     Сервер
┌──────────────────┐            ┌──────────────────────┐
│ elevator_desktop │──чтение/──▶│       MariaDB        │
│   (ПК 1, 2, …)   │   запись   │  vostok_db — заявки, │
└──────────────────┘            │    адреса, сотрудники│
                                │  site — пользователи │
┌──────────────────┐            │    сайта             │
│   elevator_web   │──чтение───▶│                      │
└──────────────────┘            │                      │
┌──────────────────┐            │                      │
│ telegram_bot     │──чтение───▶│                      │
└──────────────────┘            └──────────────────────┘
```

- **Схема базы** принадлежит десктопному приложению: она описана в `schema_db.sql` и применяется автоматически при каждом его запуске. Сайт и бот схему не меняют.
- **Модель данных:** города → улицы → дома (с управляющей компанией) → подъезды → лифты; заявки ссылаются на адрес лифта и на сотрудников (диспетчер, механик, исполнитель).
- **Несколько рабочих мест:** у каждого диспетчерского ПК свой `pc_id`, по нему заявки привязываются к рабочему месту.
- **Пользователи сайта** хранятся в отдельной базе `site` и заводятся из десктопного приложения (меню «Добавить» → «Добавить пользователя на сайт»).
- **Права в БД:** сайт подключается отдельным пользователем MariaDB с правом только на чтение (`SELECT`). Боту тоже достаточно только чтения.

## Порядок установки

1. Поднять сервер MariaDB, доступный по сети всем рабочим местам.
2. Установить **elevator_desktop** на диспетчерские ПК. При первом запуске мастер создаст пользователя приложения, базу и таблицы.
3. Установить **elevator_web** на сервер: создать пользователя БД для сайта (`create_db_user.bat`), заполнить `.env`, запустить через `install_task.bat`. Логины для входа на сайт добавить из десктопного приложения.
4. Запустить **elevator_telegram_bot**: в `.env` указать `BOT_TOKEN` и параметры подключения к БД (`DB_HOST`, `DB_USER`, `DB_PASS`, `DB_NAME`).

Подробности по каждому шагу — в README соответствующего репозитория.

## Обновления

Десктопное приложение обновляется само: раз в 6 часов оно проверяет релизы в [mitol_releases](https://github.com/Ramz4n/mitol_releases) и предлагает установить новую версию. Сайт и бот обновляются вручную (`git pull` и перезапуск).
